# 庭审编排

一次只叫一个角色。没被点到的 agent 本槽调用次数是零。不建群聊，不打开 OpenClaw broadcast。`chat.sendWithMedia` 每次只有一个 `sessionKey`。

点名的是 studio-web 宿主里的驱动器。队列和笔录在公司数据平面。浏览器只订阅，不直接 `sendWithMedia`，避免两个标签各打一次模型。

## 五个槽

| 序号 | 阶段 | 谁 | 庭审记录里带什么 |
|---|---|---|---|
| 1 | 陈述 | 原告。我方是原告且选择自己说时，这一槽是真人 | 还没有发言。只有案情摘要和本槽档案片段 |
| 2 | 陈述 | 被告 | 原告刚刚说出口的全文 |
| 3 | 询问 | 审判长 | 原告和被告已说出口的全文。审判长本场第一次被叫到，他的会话里原本没有这些话 |
| 4 | 陈述 | 我方 | 若我方会话还在，只补审判长说完之后的新发言 |
| 5 | 收束 | 书记员 | 截至当前的笔录。产出：无争议点、争议点、档案未检索到的点。不新增事实 |

陪审员占固定 agent 名额，本期不进队列。十阶段（质证、调解、评议、宣判）以后用 `moot_slot.phase` 加行，不改笔录表。

## 消息四块

顺序固定：

```
你是{角色}。现在只说你这一段。不要代替其他角色发言。
档案片段里没有的条款，写「档案未检索到」，不要写成已查明。

【案情摘要】
moot_case.summary

【庭审记录】
该角色本场第一次：截至当前的 moot_utterance 全文
同一 session 再次被叫到：只含他上次发言之后的新句
宿主声明会话丢失，或 OpenClaw 已把该会话压成摘要：再次给全文

【本槽档案片段】
0–5 段，或「本槽档案未检索到」

【现在轮到你】
moot_slot.plan
```

OpenClaw 在窗口快满时会把旧消息压成摘要（compaction）。那份摘要不能当笔录。笔录以 `moot_utterance` 为准。qwen3-max 的输入上限是 258048 token（阿里云 Model Studio 文档）。五个槽的发言原文远小于该值。撑满窗口的情况是把合同全文贴进消息，本期禁止。

## 接口

都要登录。租户从护照取。

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/moot/cases` | 建案。`signTaskId` 可空，`stance` |
| GET | `/api/moot/cases` | 列表 |
| POST | `/api/moot/cases/{id}/hearings` | 生成五个槽，状态改为 HEARING。不调用模型 |
| PUT | `/api/moot/hearings/{id}/sessions` | 宿主登记六个 `sessionKey` |
| GET | `/api/moot/hearings/{id}` | 队列、已说的话、当前槽 |
| POST | `/api/moot/hearings/{id}/turns/prepare` | 当前槽改为 SPEAKING，返回 `agentId`、`sessionKey`、`message`、`slotId`。真人槽返回 `awaitHuman=true`，不组装模型消息 |
| POST | `/api/moot/hearings/{id}/turns/commit` | `slotId`、正文、`speaker`。槽必须是 SPEAKING。写入笔录，改为 DONE |
| POST | `/api/moot/hearings/{id}/turns/skip` | 超时。槽改为 SKIPPED，笔录记「本槽未发言」 |
| POST | `/api/moot/hearings/{id}/close` | 结案。返回各 `sessionKey` 供宿主删除。服务端清空 `moot_role.session_key` |

`prepare` 对同一槽幂等。`commit` 对已 DONE 的槽拒绝。

上传和预览见 [档案与检索](./02-档案与检索.md)。

## 驱动循环

1. 读 hearing，找到 PENDING 或已 SPEAKING 的槽
2. `prepare`
3. `awaitHuman` 时通知页面，等用户提交再 `commit`
4. 否则只向返回的 `sessionKey` 发消息，收流，拼成正文
5. `commit`
6. 直到五个槽结束或用户停止

同一 hearing 只有一个驱动。后打开的页面只订阅事件：`slot-started`、`delta`、`slot-committed`、`await-human`、`hearing-closed`。

单次生成 90 秒。超时 `skip`，不重试整场。

## 真人

我方槽可以选择自己说：该槽不调用我方 agent。插话在当前槽 `commit` 之后追加一条 `speaker=HUMAN` 的已完成槽，不并行调用任何 agent。原定的下一位仍是下一位。

## 原告说完到被告开口

1. 原告正文已在 `moot_utterance`
2. `prepare` 被告槽
3. 数据平面用「被告答辩」和原告发言末段检索，至多 5 段
4. 消息含原告全文和这 5 段
5. 宿主只打被告的会话
6. `commit` 被告正文。检索摘录留在 `moot_retrieval`
7. `prepare` 审判长时，庭审记录含原告和被告已说的话，档案按「审判长询问」重新查一次

## 中断

页面关掉时，已 `commit` 的句子还在档案文件夹的 `hearing-*.json` 里。正在生成、还没交回的那句作废。再次进入从下一个 PENDING 槽继续。已 SPEAKING 但没有 commit 的槽，再次 `prepare` 返回同一份消息。

## 页面上的核对

发言里出现了具体条号，但本槽 `moot_retrieval` 的摘录里没有这个条号：该条旁标「未在本槽片段中出现」。本期不自动重生成。
