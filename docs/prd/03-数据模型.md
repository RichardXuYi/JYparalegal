# 数据存放

档案不建表。记录是档案目录里的 JSON，原件是同目录下的文件。字段名与页面一致。

## case.json

| 字段 | 说明 |
|---|---|
| id | 案卷号 |
| signTaskId | 可空，平台合同任务号 |
| stance | `PLAINTIFF` 或 `DEFENDANT` |
| summary | 1–1500 字 |
| status | `DRAFT` `READY` `HEARING` `CLOSED` |
| createdBy | 平台用户 id |
| createdAt | 时间 |

## files.json

数组。每一项：

| 字段 | 说明 |
|---|---|
| id | 文件号 |
| fileName | 原始文件名 |
| relativePath | 相对档案根目录 |
| parseStatus | `PARSED` 或 `NO_TEXT` |
| sha256 | 64 位十六进制 |
| sizeBytes | |
| chunks | 字符串数组，约 700 字一段、重叠约 100 字。页面上的「切片数」是这个数组的长度 |

原件路径：`{租户}/{案卷}/files/{文件号}-{文件名}`。

## hearing-{id}.json

| 字段 | 说明 |
|---|---|
| id / case_id / status | 一场庭审。`status` 为 `OPEN` 或 `CLOSED` |
| human_roles | `OURS` 表示我方槽由真人说，空表示全由 agent 说。我方为原告时这是第 1 槽和第 4 槽；我方为被告时这是第 2 槽和第 4 槽 |
| roles | `role_code`、`agent_id`、`session_key` |
| slots | `id`、`seq`（1–5）、`phase`、`role_code`、`status`、`plan_text` |
| utterances | `slot_id`、`role_code`、`speaker`（`HUMAN` 或 `AGENT`）、`body` |
| retrievals | `slotId`、`fileName`、`seq`、`excerpt` |

`role_code`：`JUDGE` `JUROR_A` `JUROR_B` `OURS` `OPPONENT` `CLERK`。

`slot.status`：`PENDING` `SPEAKING` `DONE` `SKIPPED`。

平台库 `V130` 不增加这些内容。
