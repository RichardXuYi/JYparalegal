# 部署与数据边界

平台库只管账号。档案和庭审正文不进 `jy_financial`，写在后端这台机器的文件夹里。

## 现在的代码

`application.yml` 里的 MySQL 仍是平台库 `jy_financial`（用户、组织、套餐、签署、证据、知识文章）。模拟法庭不往这个库加表。

登录仍走控制平面护照，租户以 `tenant_id` 为准。档案按这个租户号分子目录。

## 档案放哪

默认目录 `./data/archive`，配置项 `jy.archive.dir`，环境变量 `ARCHIVE_DIR`。

```
data/archive/
  {租户号}/
    {案卷号}/
      case.json
      files.json
      files/          原件
      hearing-{id}.json
```

不配置第二套数据库，不执行 `公司档案库/V1__archive_and_moot.sql`。

案卷上可以记平台的 `signTaskId`（一个数字）。需要合同标题时向平台已有的签署接口查，不把合同正文抄进 `jy_financial`。

## 运行时

```
浏览器
  看档案、队列、发言

studio-web 宿主
  一次只向一个角色的会话发消息
  说完把正文交回后端，后端写入档案文件夹

平台库 jy_financial
  登录、租户、套餐、已有签署
  不存切片和笔录

本机档案目录
  原件、切片、五个槽、笔录
```

律师电脑不另装 MySQL。OpenClaw 只生成发言，笔录在档案文件夹里。
