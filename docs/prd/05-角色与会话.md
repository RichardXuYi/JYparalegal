# 角色与会话

工作室固定六个角色。不按案件创建 agent。结案后删掉本场会话，下一场从空会话开始。角色配置保留。

## 六个 id

已存在则跳过创建。创建仍走现有 `createAgent`，只写 id、name、workspace、agentDir（`studio-web/server/host-core/utils/agent-config.ts`）。

| agent id | 显示名 | 本期是否进队列 |
|---|---|---|
| `moot-judge` | 审判长 | 是 |
| `moot-juror-a` | 陪审员甲 | 否，只占名额 |
| `moot-juror-b` | 陪审员乙 | 否，只占名额 |
| `moot-ours` | 我方 | 是 |
| `moot-opponent` | 对方 | 是。队列里的「被告」在我方为原告时用这个 agent |
| `moot-clerk` | 书记员 | 是 |

我方为被告时，槽 1 的原告用 `moot-opponent`，槽 4 的我方用 `moot-ours`。立场在 `moot_case.stance`，不另建 agent。

## 技能允许列表

OpenClaw 把某个 agent 能看见的技能写在 `agents.entries.<id>.skills`。不写则继承默认技能。写了非空列表就是最终集合，不与默认合并。空数组表示没有技能。文档：[Skills](https://docs.openclaw.ai/skills/)、[per-agent entries](https://docs.openclaw.ai/gateway/config-agents/entries-and-multi-agent)。

宿主增加 `agents.updateSkills(id, skillKeys)`，写入 `openclaw.json` 后走现有 gateway 热加载。副总团队的 Skill 文件到位之前，六个角色都设为 `[]`，避免继承工作室里写代码、上网一类技能。身份约束写在每一槽消息开头，不依赖 Skill 才能开庭。Skill 到位后只改允许列表，不改驱动器。

## 不做专属 MCP

现行文档里能按 agent 收窄 MCP 的字段是 `mcp.servers.<name>.codex.agents`，只作用于 Codex app-server。本项目发言走 DashScope 上的 qwen，嵌入式 OpenClaw，那个字段管不到。把服务器配进 `mcp.servers` 后，默认每个 agent 都能看见。档案不走 MCP。检索在数据平面点名前完成。

## 会话

开庭时宿主为六个角色各开一个新 `sessionKey`，`PUT /api/moot/hearings/{id}/sessions` 登记。

每一槽只向 `prepare` 返回的那个 key 发送。

`close` 成功后，对登记过的每个 key 调用已有的 `sessions.delete`（删除 jsonl，并从 `sessions.json` 去掉该 key）。删不掉的要在结案结果里报出来，下一场仍使用新 key，并再删一次旧 key。

`sessions.delete` 不会清 workspace 里的 `MEMORY.md` 和 `memory/*.md`。开庭前为这六个角色的记忆文件做空快照。结案时若文件与快照不同，恢复快照。消息模板里禁止把本案写入长期记忆。

`ensureMemorySearchDisabledDefault` 在用户没有自行配置时会把 `memory.search.enabled` 设为 false。本期不要为了档案打开它。

## 结案后的干净程度

下一场看到的是新会话、空的庭审记录，以及该案自己的档案检索。上一场说过的话只留在档案文件夹的 hearing 记录里，不留在 agent 对话里。
