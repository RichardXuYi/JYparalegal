# 二期核验报告：模拟法庭与档案库

日期：2026-09-27。基线：`docs/prd/01–08`、`docs/demo/mock-court-demo.html`（均为当前工作树内容，二期代码尚未提交 git）。

## 结论

主体框架已落地：后端 `module/moot`（本机文件夹存储、/api/moot 全套接口、五槽编排、槽前检索、消息四块）、studio-web 宿主驱动器（单会话发送、90 秒超时 skip、结案删会话与记忆恢复、六角色 skills=[]）、`/moot` 三视图页面均已按 PRD 方向实现，平台库未加表。

但存在：**4 个功能性缺陷**（其中 2 个直接破坏验收路径）、**1 处明确方向偏离**（桌面壳接入了 PRD 明令不做的第二套驱动器）、以及若干与 PRD/demo 的差距项。前端与 demo 的三视图骨架一致，但庭审视图缺「发言权/静音条」「三栏角色卡（合议庭）」两大框架块。

## 一、功能性缺陷（建议优先修）

### 1. 「已签合同」下拉永远为空
`studio-web/src/pages/MockCourt/index.tsx:58` 请求 `/platform/sign/tasks?view=全部`，但 `SignFlowService.listByView`（`backend/.../sign/service/SignFlowService.java:256-311`）没有 `全部` 这个 view，会抛 `INVALID_VIEW`。前端 `.catch(() => setTasks([]))` 静默吞掉，结果**新建案卷永远选不到签署任务**，`signTaskId` 关联功能实际不可用。两处任改其一：前端改用 `ALL_SIGNING` 或 `CREATED_BY_ME`，或后端加 `全部` 分支。

### 2. 刷新后回不到进行中的庭审，且可重复开庭
- `publicCase()`（`MootService.java:467-476`）不返回 `hearingId`，前端刷新后丢失庭审编号，庭审视图入口（按钮 3）disabled，PRD 04「再次进入从下一个 PENDING 槽继续」**在前端无入口**（后端 `GET /hearings/{id}` 本身支持）。
- `openHearing`（`MootService.java:173-216`）不检查案卷是否已处于 `HEARING`，重复点「开庭」会**生成第二场庭审**并覆盖 `caseId` 上的 `hearingId`，同案卷下堆积多个 `hearing-*.json`。
- 修法：`publicCase` 透出 `hearingId`；case 为 `HEARING` 时页面直接进入既有庭审；`openHearing` 对 `HEARING` 状态拒绝或幂等返回。

### 3. 真人槽只支持第 4 槽，PRD/demo 的「原告自说」场景缺失
PRD 04 槽 1 明确「我方是原告且选择自己说时，这一槽是真人」，demo 也把槽 1 标为真人（原告·我方）。后端硬编码 `human_roles="4"` 且 `prepare` 只认第 4 槽（`MootService.java:182,239`），前端复选框文案即「第 4 槽我自己说」（`index.tsx:252`）。结果：我方=原告自说时，**原告陈述由 agent 代说，真人只能在第 4 槽补充**，与 PRD 04 和 demo 相反。PRD 03（human_roles 只写了 "4"）与 PRD 04 自身有矛盾，需要先定稿再改。

### 4. web 壳上传大文件必失败（413）
上传走 JSON+base64，经 Fastify 代理转发。Fastify `bodyLimit: 16MB`（`studio-web/server/src/index.ts:212`），base64 膨胀约 1.37 倍，**实际只能传约 12MB 原件**，而 PRD/后端宣称 50MB。桌面壳无此限制（IPC 直转发）。这同时暴露了与 PRD 的偏离：PRD 02 要求 **multipart 上传**，现在是 base64 JSON（`MootController.java:46-49`）。改成 multipart 直传后此问题一并消失。

## 二、方向偏离（与 PRD 明文相悖）

| # | 偏离 | PRD 要求 | 现状 |
|---|---|---|---|
| 1 | **桌面壳接了第二套驱动器** | PRD 06：「桌面壳 studio-frontend 的同名占位页保持占位，不接第二套驱动器。庭审以 studio-web 为准」 | `studio-frontend/src/pages/MockCourt/index.tsx` 与 web 版**逐字节相同**；另有 `electron/services/moot-desktop-step.ts` + `ipc-handlers.ts:1150-1156` 拦截 step 请求，构成第二驱动器 |
| 2 | 桌面驱动器缺全套保障 | PRD 05/07 D、E、F | 桌面驱动无 `ensureRoles`（不建六 agent、不写 skills=[]）、无记忆快照/恢复、**结案不删会话**（cleanup 只调 Java close，不调 sessions.delete）、超时不 skip（槽停留 SPEAKING）、无单驱动锁 |
| 3 | 上传协议 | PRD 02：multipart，50MB | JSON+base64，见缺陷 4 |
| 4 | 解析状态无 `FAILED` | PRD 02：解析失败置 FAILED、错误信息落在该行 | `ArchiveText.extract` 异常一律返回空串 → 一律 `NO_TEXT`（`MootService.java:113-114`）；损坏文件被误标「无文字层」 |
| 5 | 插话未实现 | PRD 04 真人节：当前槽 commit 后可追加 `speaker=HUMAN` 已完成槽，不影响下一位 | `commit` 只接受 SPEAKING 槽（`MootService.java:275`），无独立插话端点；仅第 4 槽 awaitHuman 一种真人路径 |
| 6 | 事件契约不符 | PRD 04/06：`slot-started`、`delta`、`slot-committed`、`await-human`、`hearing-closed` | 实际只有 `human`/`delta`/`error`/`done`（`moot-driver.ts:155-157`），缺 `slot-started`、`hearing-closed`，命名不一致 |
| 7 | 第二窗口只读未实现 | PRD 04/06：后打开的页面只订阅事件看进度 | 事件只走发起 step 的那条 SSE；第二窗口无任何订阅/轮询，视图冻结。单驱动锁也只是**单次 step 内**的内存锁（`moot-driver.ts:145-148`），两个标签可轮流按按钮 |
| 8 | `sessionLost` 通道建成但从未使用 | PRD 04：宿主声明会话丢失或 OpenClaw 压缩后重发全文 | 后端支持 `?sessionLost=true`（`MootController.java:87`），web 驱动器从不传（`moot-driver.ts:160`），也未检测 compaction |
| 9 | 会话删除失败未上报、旧 key 不补删 | PRD 05：删不掉要在结案结果报出，下一场再删一次 | `moot-driver.ts:243-244` `.catch(() => undefined)` 静默吞错；无旧 key 重删机制 |
| 10 | 案卷无合同标题回查 | PRD 01：需要合同标题时向平台签署接口查 | `publicCase` 只回数字 `signTaskId`，无标题回查；且见缺陷 1（下拉本来就空） |
| 11 | 公司级制度文件不支持 | PRD 02：制度文件可不挂案卷（case_id 为空） | 所有文件必须挂在案卷下（`MootService.upload` 必传 caseId） |
| 12 | 导航文案未更新 | PRD 06：入口沿用 `/moot` | `studio-web/src/components/layout/nav-config.ts:81-82`、`studio-frontend/src/pages/Features/index.tsx:76`、两处 Overview 卡片仍写「即将开发」 |

另有两处小残留：`ArchiveProperties.java:9-11` 留着第二数据库方案的 `url/username/password` 死字段（PRD 01 明确不接第二库）；`moot-driver.ts:81-89` `waitForReply` 是死代码。

## 三、按 PRD 逐项核验

### 01 部署与数据边界 — 基本符合
- 本机文件夹存储、`jy.archive.dir` / `ARCHIVE_DIR`（`application.yml:89-90`）✅
- 平台库无新表（`db/migration` 无 moot 表；`V1__archive_and_moot.sql` 仅残留于 `target/classes/db/migration-archive/`，Flyway 只扫 `db/migration`，不会执行）✅
- `/api/moot/**` 挂在登录+套餐门禁之后（`WebConfig.java:48-52`），租户取自上下文，档案按租户分目录 ✅
- 残留：ArchiveProperties 死字段（见上）；`signTaskId` 标题回查未做。

### 02 档案与检索 — 主体符合，四处差距
- 50MB 上限、扩展名白名单、路径逃逸防护（normalize + startsWith）、sha256 ✅（白名单比 PRD 多 txt/md/csv）
- docx→POI、pdf→PDFBox ✅；**无 FAILED 状态**、无错误信息落行 ✗
- 切段：固定 700 字窗口 + 100 重叠（`MootService.java:591-604`），PRD 是「按段落累加 500–800 字」——结果可用，做法偏离；无页码/段落定位（PRD 允许「取到才填」，实际从未填）
- 检索：服务端拼查询句（plan + 末段 tail）✅；只查本租户本案卷 ✅；条号整段 needle ✅（`MootService.java:606-611`）；最多 5 段、每段 800 字 ✅；命中写入 retrievals ✅；零命中提示 ✅；NO_TEXT 不参与 ✅
- 「金额、日期按整段匹配」未实现（needle 只识别第×条，其余取前 40 字）△
- 摘录不进 utterance、下一位只见已说出的话 ✅
- 预览：功能在但路径为 `GET /files/{fileId}` 而非 PRD 的 `/content`（小）；每次预览**重新解析原件**而非用已存结果（小）；`raw=true` 供打开原件 ✅

### 03 数据模型 — 符合
case.json / files.json / hearing-{id}.json 字段与 PRD 一致（hearing 多了 started_at/closed_at，utterance 多了 char_count，均无害）；role_code 六值、slot 五状态齐全；切片即字符串数组。`V130` 未动 ✅。

### 04 庭审编排 — 主体符合
- 一次只叫一个、无群聊、无 broadcast ✅；驱动在宿主、浏览器不直接 sendWithMedia ✅
- 五槽及立场换位（我方=被告时槽 1 用 opponent）✅；陪审员不进队列 ✅
- 消息四块及「同一 session 只补新句 / sessionLost 重发全文」✅（`MootService.message`）
- prepare 同槽幂等（检索按槽缓存）✅；commit 拒绝重复 ✅；skip ✅；close 返回 keys 并清空 ✅
- 接口表 9 条全部实现（另有额外的 `/archive` 状态、`/cases/{id}/search`）
- 差距：真人仅第 4 槽（缺陷 3）、插话缺失（偏离 5）、事件契约（偏离 6）、90 秒超时 skip 仅 web 有 ✅、刷新恢复前端断裂（缺陷 2）

### 05 角色与会话 — web 符合，桌面缺失

## 五、驱动器实现质量提示（非 PRD 条文，但影响 D/E 验收稳定性）

- 完成判定用「连续 2 次轮询文本不变」（约 2.4 秒，`moot-driver.ts:199-211`）即提交：模型生成中途停顿超过 2.4 秒时，**会把半截发言 commit 进笔录**。建议改为等 gateway 侧的完成信号或加长稳定窗口。
- delta 为 1.2 秒全量轮询 `chat.history`，非流式增量；每个 tick 都重新拉 30 条历史，长庭审有放大开销。
- `chat.sendWithMedia` 的 `idempotencyKey` 每次随机（`moot-driver.ts:194`）：step 中断重试时同一消息可能重复进会话。
- 桌面驱动器（`moot-desktop-step.ts`）与 web 驱动器是两份平行代码，行为已出现分叉（超时处理、锁、清理都不同）——这正是 PRD 06 禁止第二驱动器的原因。

## 六、建议处理顺序

1. 修缺陷 1（view=全部）与缺陷 2（hearingId 透出 + 防重复开庭）——小改动，恢复验收 C/E 路径。
2. 决策桌面壳去留：按 PRD 回退为占位（删 `moot-desktop-step.ts` 与整页复制），或修订 PRD 承认桌面为正式入口并补齐 ensureRoles/删会话/记忆恢复/skills。**二选一，不要维持两份分叉驱动器。**
3. 上传改 multipart（一并解决 16MB 上限与 PRD 偏离），补 FAILED 状态。
4. 定稿真人槽语义（PRD 03 vs 04/demo 的矛盾），支持我方=原告时槽 1 真人；补插话端点。
5. 事件契约对齐（slot-started/slot-committed/await-human/hearing-closed），第二窗口订阅。
6. 前端补 demo 的两块框架（发言权/静音条、三栏角色卡）与右栏摘要，更新导航「即将开发」文案。
7. 其余小项（FAILED 落行、删除失败上报、切段按段落、清理死代码/死字段）。
8. 全部二期改动目前**未提交 git**，建议尽快分批提交。
