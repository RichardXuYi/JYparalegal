## 1. 问题现象

- 每次在 Studio（Chat 顶栏模型选择器 / 设置页）切换模型，都会弹出**全局阻塞遮罩**（`ConnectionStatusModal`）：先显示「正在切换模型…」，随后网关进程重启、WS 断开，遮罩切文案为「正在重新连接…」，等待 10–30 秒网关重启完成后才消失。
- 每次切模型 = 整个 OpenClaw Gateway 进程重启，**连带 WhatsApp / Telegram / 飞书 / 企微等渠道适配器一起重启重连**（Channels 页面代码自注释：*"Channel adapters can take time to reconnect after gateway restart"*）。
- Web 端 Fleet 模式（每用户独立 Gateway 子进程）同样受影响，并放大端口 / 生命周期管理风险（1.4.66 修的「端口双源 / 重连死循环」正是这一族问题的表现）。

## 2. 根因分析

### 2.1 当前切模型的完整链路（双端同构）

```
ChatInput.tsx: beginModelSwitch()                        ← 全局阻塞弹窗「正在切换模型…」
  → hostApi.agents.updateModel(agentId, modelRef)        (electron/services/agents-api.ts:70)
    → updateAgentModel()                                 (electron/utils/agent-config.ts:666)
        直接改写 ~/.openclaw/openclaw.json 的 agents.list[].model.primary
    → syncAllProviderAuthToRuntime()
      + syncAgentModelOverrideToRuntime()                （再镜像写一串 agent models.json）
    → scheduleGatewayReload() → debouncedReload()        (gateway/manager.ts:743, 防抖 1200ms)
      → reload()                                          (gateway/manager.ts:690-737)
        → 向网关进程发 SIGUSR1（Windows 直接全量 restart）
          → OpenClaw 收到 SIGUSR1 = 进程重启
            → WS 断开 → renderer 进入 reconnecting → 弹窗切「正在重新连接…」
            → 网关重启 10–30s → 重连成功 → 弹窗消失（useMinLoading 最少还要闪 600ms）
```

### 2.2 两个致命点

1. **`reload()` 本质就是重启。** OpenClaw 收到 SIGUSR1 的官方行为就是 restart（[openclaw/openclaw#74975](https://github.com/openclaw/openclaw/issues/74975) 的日志直接可见 `[gateway] received SIGUSR1; restarting`）。因此 `debouncedReload` 的「reload 模式」从来没有热过；Windows 分支更是无条件全量重启（`manager.ts:707-714`）。
2. **「写文件 + 主动重启」这条路整体多余。** 它是老版本 OpenClaw「模型配置变更必须重启网关」时代的产物——即本方案要偿还的技术债。顺带的重伤：渠道适配器每次跟着网关进程一起重启。

| 桌面端 | Web 端 | 职责 |
| --- | --- | --- |
| `studio-frontend/src/pages/Chat/ChatInput.tsx:516` | `studio-web/src/pages/Chat/ChatInput.tsx` | `beginModelSwitch` 触发阻塞弹窗 |
| `studio-frontend/src/stores/connection-status.ts` | `studio-web/src/stores/connection-status.ts` | `modelSwitch` 全局状态 |
| `studio-frontend/src/components/common/ConnectionStatusModal.tsx` | 同左 | 阻塞遮罩（model / reconnecting / connecting 三态） |

## 3. 官方能力调研（OpenClaw 2026.6.10，均已具备）

| 能力 | 官方说明 | 对本方案的意义 |
| --- | --- | --- |
| **配置热重载** | 热重载表明确：`agents`、`models`、`auth.order`、`auth.profiles`、`broadcast` 等变更**热生效，不需要 Gateway 重启**（[Config hot reload](https://docs.openclaw.ai/gateway/configuration/hot-reload)） | 「切模型 ≠ 重启」的前提在当前版本成立 |
| **`config.patch` RPC** | 部分更新（JSON merge patch）+ `baseHash` 乐观锁；**热生效变更会等网关应用完成后才返回**，响应含 `changedPaths`；带 `id` 的对象数组默认按 id 合并、不动其他条目（[Config RPC](https://docs.openclaw.ai/gateway/configuration/config-rpc)） | 程序化写 agent 默认模型的标准姿势，替代「写文件 + 重启」 |
| **`sessions.patch` 会话级模型覆盖** | `{ key, model: "provider/model" }` 只改当前会话，零配置写入；`/model <m> -s` 同语义（[Models FAQ](https://docs.openclaw.ai/help/faq-models)） | Chat 顶栏切模型的完美对应物，**与已上线的 `thinkingLevel` 完全同模式**（`gateway.rpc('sessions.patch', …)`） |
| **幽灵重启 bug 已修** | `config.patch` 改模型触发意外重启（[#74975](https://github.com/openclaw/openclaw/issues/74975)）在 **v2026.4.27** 修复 | 2026.6.10 > 2026.4.27，无需升级 |
| **会话级覆盖不生效 bug 已修** | `sessions.patch` 模型覆盖在 `chat.send` 不生效（[#60270](https://github.com/openclaw/openclaw/issues/60270)）已于 2026-04-04 关闭 | 同上，当前版本可用 |

> 边界备忘：`config.patch` / `config.apply` 控制面限速 30 次 / 60 秒（按 method × deviceId+clientIp）——对手动 UI 操作绰绰有余；`gateway.reload.mode` 官方只有 `hybrid`（默认）/ `off`，早期 `hot` / `restart` 模式已废弃。

## 4. 方案总览

**目标：切模型从「10–30s 阻塞弹窗 + 网关进程重启 + WS 重连 + 渠道重连」变为 <1s 静默完成。**

**原则：**

1. 网关在线时，一切模型类变更走 **Gateway RPC**（OpenClaw-owned write，应用有确认、有 `changedPaths` 回执），不再由 Studio 直写配置文件后自行重启。
2. 网关离线时才允许离线文件写入（无需任何 reload，网关下次启动自然读到最新配置）。
3. 全量 `restart()` 只保留给真正需要的场景：删除 agent、网关服务器级配置变更（端口 / auth mode / TLS）、用户手动点「重启网关」。

### 实施路线（按收益排序）

```
Phase 1  Chat 会话级切模型 → sessions.patch          （消灭 ~90% 弹窗，改动最小）
Phase 2  Agent 默认模型   → config.patch RPC         （设置页 / "设为默认" 场景）
Phase 3  收敛自家 reload 机制（SIGUSR1 路径退役）      （还技术债）
Phase 4  UI 收尾 + 双端镜像 + harness 验收            （流程合规）
```

## 5. Phase 1：Chat 会话级切模型改走 `sessions.patch`

### 5.1 改动内容

- `ChatInput.tsx` 的模型选择器不再调 `hostApi.agents.updateModel`，改为（经 host-api 代理，遵循「渲染层不得直连 Gateway」规则）：

  ```ts
  await gatewayRpc('sessions.patch', { key: currentSessionKey, model: modelRef });
  ```

- **直接复制 `setThinkingLevel` 的现成模式**（1.4.66 已上线）：乐观更新 + 失败回滚 + toast 报错。
- 零配置写入、零 reload、零重连、零弹窗，切换瞬时完成。

### 5.2 会话 key

`thinkingLevel` 链路已在 ChatState 中持有当前会话 key（`agent:<agentId>:…`），直接复用。

### 5.3 语义说明（对应官方交互）

- 会话级切换 = 官方裸 `/model <model>`（只影响当前会话，不落盘）。
- 模型 ref 必须是 `provider/model` 全称（`sessions.patch` 会拆分为 `providerOverride` + `modelOverride`）。
- 与 thinkingLevel 一样，新会话回到 agent 默认模型。

### 5.4 验收标准

- [ ] 切换后下一条 `chat.send` 实际运行在新模型上（从会话 transcript 的 `message.usage` / 模型归因字段核对，勿只看 UI）。
- [ ] 全程 `ConnectionStatusModal` 不出现；WS 连接不断开；Gateway pid 不变。
- [ ] 切换失败（模型不存在 / provider 未配置）有 toast，且 UI 回滚。

---

## 6. Phase 2：Agent 默认模型改走 `config.patch` RPC

### 6.1 改动内容

`agents-api.ts` 的 `updateModel`，网关在线（`gatewayManager.isConnected()`）时改为：

1. `config.get` → 取当前 `hash`；
2. `config.patch` 提交部分对象：

   ```json
   {
     "raw": "{\"agents\":{\"list\":[{\"id\":\"<agentId>\",\"model\":{\"primary\":\"<provider/model>\"}}]}}",
     "baseHash": "<hash from config.get>"
   }
   ```

   - `agents.list` 是带 `id` 的对象数组，官方 merge-by-id 语义会**只改该条目的 model 字段、保留其余条目与字段**；本场景不删除数组条目，**不需要 `replacePaths`**。
   - `modelRef = null`（清除默认）时提交 `{"id":…}` 并置 `model: null`（merge patch 中 null = 删除该键）。
3. 响应 `changedPaths` 只含 `agents.*` 路径 ⇒ 热生效，直接刷新 agents 快照返回，**全程无重启无重连**；
4. `baseHash` 冲突（并发改写）⇒ 重读 hash 重试一次，再失败则报错。

网关离线时保留现有 `updateAgentModel()` 文件写入路径（去掉其后的 reload 调度——离线场景无需 reload）。

### 6.2 实施前必做核对

- 先用 `gateway.rpc('config.schema.lookup', { path: 'agents.list' })` 核对 `agents.list` 条目级 patch 的确切 schema 形态（官方推荐 `config.schema.lookup` 为写前第一站）。
- 同步评估**退役 `syncAgentModelOverrideToRuntime` / `syncAllProviderAuthToRuntime` 在切模型场景的调用**：它们是配合「重启」而生的 models.json 镜像补丁；走 RPC 后 openclaw.json 由网关自己管理，agent 目录镜像是否仍必要需实测确认（provider key 场景另议，先只动模型字段链路）。

### 6.3 验收标准

- [ ] 设置页改默认模型后，Gateway pid 不变、WS 不断开、弹窗不出现。
- [ ] 新会话使用新默认模型；`config.get` 回读确认 `agents.list[].model.primary` 已更新。
- [ ] 并发连续切换（快速连点多个模型）不产生 `baseHash` 死循环，最终值一致。
- [ ] 网关停止状态下改模型，启动后配置生效（离线路径回归）。

## 7. Phase 3：收敛自家 reload 机制（还技术债）

### 7.1 改动内容

- **SIGUSR1「reload」路径退役**（`manager.ts` `reload()`）：它在 OpenClaw 侧就是 restart，留着只会制造「看起来热了其实没热」的假象；Windows 的无条件全量重启回退随之消失。
- `reload-policy.ts` 的 `hybrid / reload / restart / off` 四模式收敛，对齐 OpenClaw 官方 `gateway.reload.mode` 语义（`hybrid` 默认 / `off`）；文档化「模型 / agent / provider 类变更不触发任何应用侧 reload」。
- `debouncedReload()` 调用方逐一梳理（agents-api / providers-api / channels-api / provider-runtime-sync）：模型类变更全部移除调度；保留项见 7.2。

### 7.2 `restart()` 保留清单

| 场景 | 现状 | 处理 |
| --- | --- | --- |
| 删除 agent | `restartGatewayForAgentDeletion` 全量重启 | 暂保留（另立后续优化项：评估 agent 热摘除） |
| 网关服务器级配置（端口 / auth mode / TLS / bind） | — | 保留 restart（官方也要求） |
| 渠道 / 插件安装升级 | `channels-api` / `plugin-install` 部分依赖重启 | 逐项对照官方热重载表，能热则热，不在本方案强推 |
| 用户手动「重启网关」按钮 | Settings / Channels 页 | 保留 |

### 7.3 验收标准

- [ ] 全代码库搜索不到「模型切换 → restart/ SIGUSR1」路径；`pnpm run comms:replay` + `comms:compare` 基线更新且无回归。

## 8. Phase 4：UI 收尾 + 双端镜像 + 流程合规

### 8.1 UI

- `ConnectionStatusModal` 移除 `model` 分支；`connection-status.ts` 的 `modelSwitch` 状态与 `ChatInput` 的 `beginModelSwitch/endModelSwitch` 退役；`user-session-reset.ts` 引用同步清理。
- 遮罩只保留给**真实的**初次连接 / 断线重连；Agent 默认模型变更（Phase 2）用设置行内 spinner 替代全局阻塞。
- `useMinLoading(600)` 的「最少闪 600ms」逻辑对快速操作重新评估（保留给真实重连场景）。

### 8.2 双端镜像

所有改动同步到 `studio-web/server/host-core/`（agents-api / gateway/manager / reload-policy / provider-runtime-sync 同源路径）及 `studio-web/src/` 对应页面与 store；Fleet 模式下验证 Worker 级 Gateway 同样无重启切换。

### 8.3 流程合规（AGENTS.md 硬性规则）

- [ ] `harness/specs/tasks/` 新建 task spec，scenario 引用 `gateway-backend-communication`；实施前 `pnpm harness validate --spec <task-spec>`，实施后 `pnpm harness run --spec <task-spec>`。
- [ ] 通信路径变更跑 `pnpm run comms:replay` + `pnpm run comms:compare` 后再提交。
- [ ] `pnpm run typecheck` + `pnpm run lint:check` 同 PR 通过。
- [ ] i18n：新增 / 变更文案走 `react-i18next`，`en / zh / ja / ru` 四语言全量补 key（含失败 toast 文案）。
- [ ] 文档同步：`README.md` / `README.zh-CN.md` / `README.ja-JP.md` 行为说明更新（「切模型不再重启网关」）；studio-web / studio-frontend 各自 README 变更记录表追加条目。
- [ ] 按仓库规则，若形成可复用的通信约束，同 PR 更新 harness 的 scenario / rule spec。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| `agents.list` patch 形态与官方 schema 不完全一致 | 中 | 实施前 `config.schema.lookup` 核对（6.2）；先用 `openclaw gateway call config.patch` 手工验证一次再写代码 |
| `baseHash` 并发冲突 | 低 | Main 侧沿用 `withConfigLock` 串行化 + 冲突重试一次 |
| 会话级覆盖在某些 runtime（如 codex）语义差异 | 低 | Phase 1 验收明确「下一条消息实际模型」核对项；异常时回退 Phase 2 路径 |
| models.json 镜像退役引发 agent 级配置漂移 | 中 | 退役前双写并行一个版本，实测 agent 目录读取行为后再移除 |
| 老用户 openclaw.json 中残留历史脏结构 | 低 | `config.patch` 走网关 schema 校验，非法写入会被网关拒绝并返回明确错误（比现在直写文件更安全） |
| E2E 缺位（Playwright 已于 v1.4.60 移除） | — | 以 harness spec + comms replay + 手工验收清单兜底 |

## 10. 待拍板决策点

**聊天顶栏模型选择器的语义**（影响 Phase 1 范围）：

- **A. 会话级（推荐）**：聊天内切换只影响当前会话、不落盘为默认（与 OpenClaw 官方交互一致）；另设「设为默认」入口走 Phase 2。
- **B. Agent 默认级**：聊天内切换即改 agent 默认（`-a` 语义），每次切换写盘但同样无重启无弹窗。
- **C. 可配置**：对齐官方 `agents.defaults.modelSelectionScope`，让用户自选作用域（实现成本最高，可后置）。

## 11. 预期收益

- 切模型从「10–30s 阻塞弹窗 + 网关重启 + WS 重连」变为 **<1s 静默完成**；
- 切模型**不再连带弹跳 WhatsApp / Telegram / 飞书 / 企微渠道适配器**（渠道稳定性隐性大修复）；
- Fleet 模式每用户 Gateway 的重启 / 端口 / 生命周期风险面收敛（1.4.66 一族问题的根治方向）；
- `reload()` 假热重载路径退役后，「技术债清单」中 OpenClaw 集成层的历史负担减一。
